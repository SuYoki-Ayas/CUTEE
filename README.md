# CUTEE · 单学生成绩管理

CUTEE 是一个 **Windows 单机离线** 的 Qt Widgets 桌面工具，用于维护 **一位学生** 的考试成绩。

> 产品定位已从早期的“多学生考试工具箱”调整为“**单学生成绩管理**”。旧版本的多学生名单、在线作答、交卷、自动评分与旧数据迁移功能均已移除；程序只创建并读写当前的单学生表结构。

## 功能

- **学生档案**：首次启动引导填写姓名、所在学段（小学/初中/高中）、入学年份、目标院校；全库只允许存在一条档案，之后只能编辑。年级由“入学年份 + 系统日期”推算（每年 9 月升一级，初中 3 年级自动升为高中 1 年级），不需要手工维护。
- **科目管理**：科目 CRUD，分为 **OI 竞赛**（CSP-J、NOIP、模拟赛、算法专题等）与 **文化课**（语文、数学、英语、物理等）。支持排序、启用/停用；被成绩引用的科目不能删除，只能停用。
- **成绩管理**：新增、编辑、删除、按考试类型/科目/日期筛选、关键字搜索；自动计算得分率，列表默认按考试日期倒序。
- **成绩汇总**：按科目、按考试类型分别统计考试次数、平均得分、平均得分率、最高分、最低分、最近一次成绩；支持全部时间、本学期、自定义起止日期。页内分「汇总表 / 成绩趋势」两个标签页，趋势图按科目展示得分率随考试日期的变化。
- **CSV 导出**：导出当前筛选下的成绩明细，或当前时间范围的汇总（UTF-8 BOM，Excel 可直接打开）。
- **数据库备份与恢复**：设置页「数据备份与恢复」可把全部数据**导出**成单个 `.db` 文件，也可**导入** `.db` 覆盖当前数据；「重置数据」清空全部档案、科目与成绩。「导入」与「重置」都会先弹出二级验证窗口（必须手动输入「导入」/「重置」才能继续），并在执行前自动把当前数据备份到 `backups/` 目录。
- **设置 / 日志**：数据目录、日志级别、数据库版本与备份说明。
- **分组侧栏**：顶层类别为「档案」「考试」「设置」；「考试」下为成绩管理/成绩汇总/科目管理，「设置」下为设置/日志。点击类别行展开或收起二级菜单。侧栏标题下方显示学生姓名（粗体二级标题）、推算出的年级（灰色小字，如“初中·2年级”）与目标院校（灰色小字“目标：华中师大一附中”，未填写时隐藏）。
- **表格列配置**：成绩表可通过「列」菜单显示/隐藏任意列，选择会持久化，下次启动恢复。
- **快捷键**：`Ctrl+1…6` 切换页面；成绩页 `Ctrl+N/Ctrl+E/Ctrl+F/F2/Delete`，科目页 `Ctrl+N/F2/Delete`，档案与设置页 `Ctrl+S`，汇总页 `Ctrl+E`，日志页 `F5`。

本期不包含：多学生、考生名单、联考、在线作答、自动交卷/评分、代码测评、账号、云同步。

## 构建

要求：

- Windows 10/11 x64
- Qt 6.5 及以上（Widgets、Sql、Concurrent、Test、**Charts**）
- CMake 3.21+
- MSVC 2022（推荐）或 MinGW 13 验证构建

> 成绩趋势图使用 Qt Charts（`QChartView`，纯 Widgets，不引入 QML）。Qt Charts 属于 Qt 附加模块，采用 GPLv3 / 商业双许可；若安装的 Qt 未包含该模块，请在 Qt Maintenance Tool 中勾选 *Qt Charts* 后重新配置。

```powershell
$env:QTDIR = 'D:\Qt\6.11.1\msvc2022_64'
cmake --preset windows-msvc
cmake --build --preset windows-msvc
ctest --test-dir build --output-on-failure
```

仓库同时提供 `windows-mingw` 预设（Ninja + MinGW）。使用前设置 `QTDIR`、`MINGW_BIN`、`NINJA_DIR`，运行 ctest 时需把 Qt 的 `bin` 目录加入 `PATH`，否则会因找不到 Qt DLL 而失败：

```powershell
$env:QTDIR = 'D:\Qt\6.11.1\mingw_64'
$env:MINGW_BIN = 'D:\Qt\Tools\mingw1310_64\bin'
$env:NINJA_DIR = 'D:\msys2\ucrt64\bin'
$env:PATH = "$env:QTDIR\bin;$env:MINGW_BIN;$env:PATH"
cmake --preset windows-mingw
cmake --build --preset windows-mingw
ctest --test-dir build-mingw --output-on-failure
```

> 构建工具（`cmake` / `ctest` / `ninja`）统一使用 MSYS2 的 UCRT64 版本（`pacman -S mingw-w64-ucrt-x86_64-cmake
> mingw-w64-ucrt-x86_64-ninja`）。`ninja` 只按绝对路径引用，不要用它替代编译器：Qt 6.11 的 MinGW 构建基于
> `msvcrt.dll`，编译器必须保持 Qt 自带的 MinGW 13.1，否则会在跨 CRT 传递 C++ 对象时出问题。
>
> 运行时注意 `PATH` 顺序：`D:\MSYS2\ucrt64\bin` 若排在 `D:\Qt\6.11.1\mingw_64\bin` 之前，exe 会加载 UCRT 版
> `libstdc++`。`ctest --preset local-mingw` 已在 test preset 中前置 Qt 的 `bin`，手动运行 exe 时保持一致。
>
> 也可以把上面三个变量写进 `CMakeUserPresets.json`（已 gitignore）做成 `local-mingw` 预设，之后直接用
> `cmake --preset local-mingw`、`cmake --build --preset local-mingw`、`ctest --preset local-mingw`。

## 数据目录

默认使用 Qt 的 `AppDataLocation`（Windows 上通常为 `%APPDATA%\CUTEE\CUTEE`），包含：

| 文件 | 说明 |
| --- | --- |
| `cutee.db` | SQLite 数据库（WAL 模式） |
| `logs/cutee.log` | 运行日志 |
| `backups/` | 「导入」「重置」前自动生成的 .db 快照，以及「导出数据库」的默认保存位置 |

可通过环境变量 `CUTEE_DATA_DIR` 覆盖数据目录（测试与便携部署使用）。

### 备份、导入与重置

- **导出数据库**：设置页 →「数据备份与恢复」→「导出数据库…」，用 `VACUUM INTO` 生成一致性快照（含 WAL 中尚未合并的改动），得到一个可独立打开的 `.db` 文件。
- **导入数据库**：选择 `.db` 后会先校验（是否为 CUTEE 数据库、schema 版本是否过新），再弹出**二级验证窗口**，必须手动输入「导入」才能继续。确认后：自动备份 → 关闭连接 → 用所选文件替换 `cutee.db` → 重新打开并迁移 → 刷新所有页面。若替换或迁移失败，会自动从备份还原，不会留下空库。
- **重置数据**：同样经过二级验证（输入「重置」），先自动备份，再删除 `student_profile`、`subjects`、`exam_records` 三张表的全部记录并重置自增计数；`settings`（日志级别、窗口位置、成绩表列配置）与 schema 保留。
- 二级验证窗口的确认按钮在输入匹配前始终禁用，Enter 默认落在「取消」上，避免误触。

## 数据库与迁移

`schema_version` 记录当前版本，迁移在事务中执行，失败会回滚并写入日志。当前为 v3：

- **v2**：
  - `student_profile`：固定单行（`id = 1`，`CHECK (id = 1)`）。
  - `subjects`：`type` 为 `OI` 或 `ACADEMIC`，`(type, name)` 大小写不敏感唯一；`enabled` 控制是否可用于新成绩。
  - `exam_records`：`exam_type` 区分 OI/文化课，`subject_id` 外键 `ON DELETE RESTRICT`；`rank`、`participants` 可为空；`detail_json` 为后续 OI 多题明细预留（本期 UI 只录总分）。
  - `settings`：键值对配置（日志级别、窗口几何、最后停留页面）。
- **v3（当前）**：`student_profile` 新增 `stage`（`PRIMARY` / `JUNIOR` / `SENIOR`）与 `enrollment_year`（进入该学段的年份，`0` 表示未填写），用于推算年级。早期的 `student_no` / `school_class` 列保留但不再读写，旧档案升级后显示“未填写学段”，重新保存即可补全；`note` 列现存放**目标院校**（界面字段名）。

早期版本的 `students` / `questions` / `exams` / `answers` / `scores` 等旧表与旧数据迁移已全部移除：新建数据库只会创建上表，不会读取、复制或删除任何旧表；若数据目录来自更早的版本，程序仍然可以正常升级到当前 schema，但旧表不再被引用。

分数一律以 **百分之一分的整数** 保存（`152.5` 存为 `15250`），避免浮点累加误差；界面与 CSV 按两位小数以内格式化。考试日期以 `yyyy-MM-dd` 保存；创建/更新时间以 UTC ISO-8601 保存，界面按本地时间展示。

“本学期”定义为：`2 月 1 日 – 8 月 31 日`，或 `9 月 1 日 – 次年 1 月 31 日`（跨年）。

## 项目结构

```
resources/
  cutee.qrc                     Qt 资源清单（样式表与图标）
  styles/app.qss                唯一的全局样式表（浅色主题）
  icons/*.svg                   表头排序箭头等小图标
src/
  app/       main.cpp、MainWindow（导航壳）、Theme（Fusion + 调色板 + QSS + 高 DPI）
  core/      模型、时间/分数工具、汇总计算、CSV
  storage/   Database、迁移、数据导入导出/备份/重置、各 Repository、设置
  service/   ScoreService（校验/汇总/CSV）
  ui/        UiKit / Palette / TagDelegate / DangerConfirmDialog 公共构件、
             ScoreTableModel（表格模型 + 过滤代理）、
             TrendChart（Qt Charts 成绩趋势）、学生档案、科目、成绩、汇总、设置、日志页面
tests/       tst_database、tst_scores、tst_summary、tst_score_model、tst_school_stage、
             tst_data_maintenance、tst_danger_dialog、tst_profile_page、tst_settings_page、
             tst_trend_chart
```

UI 不直接拼 SQL；校验与汇总逻辑集中在 `ScoreService` 与 `core/ScoreSummary`，便于单元测试。逐文件的职责说明见 [AGENTS.md](AGENTS.md)。

## 界面结构与样式

- **主窗口**：左侧 `QTreeWidget` 分组导航（顶层类别“档案”“考试”“设置”，“考试”下有成绩管理/成绩汇总/科目管理，“设置”下有设置/日志）+ `QStackedWidget` 页面区，默认尺寸 1240×800，最小尺寸 1024×680；窗口几何与最后停留页面保存在 `settings` 表。类别行加粗、子项缩进，点击类别行展开/收起二级菜单。标题下方为学生信息块：`studentName`（粗体二级标题）与 `studentGrade`（灰色小字，如“初中·2年级”），未建档时隐藏。
- **页面快捷键**：`Ctrl+1` 档案、`Ctrl+2` 成绩管理、`Ctrl+3` 成绩汇总、`Ctrl+4` 科目管理、`Ctrl+5` 设置、`Ctrl+6` 日志。
- **主题**：`main()` 依次调用 `cutee::theme::applyHighDpiPolicy()`（在构造 `QApplication` 之前）与 `cutee::theme::apply(app)`。后者设置 Fusion 风格、显式浅色 `QPalette`、微软雅黑字体，并加载 `:/styles/app.qss`。**当前只提供浅色主题**，不随系统深色模式切换，从而避免白底白字。
- **配色**：五色柔和配色，定义在 `src/ui/Palette.h` 与 `app.qss` 两处（保持一致）：
  | 颜色 | 色值 | 用途 |
  | --- | --- | --- |
  | 薄荷绿 | `#C4F2C8` | 成功、启用、空状态底色 |
  | 淡紫 | `#E6DAF7` | 主操作按钮、表格与导航选中态 |
  | 黄绿 | `#E7EBC3` | 警示、低得分率、文化课标签 |
  | 蓝紫 | `#D8DDF0` | 表头、信息提示块 |
  | 淡粉 | `#EDD1D1` | 危险操作、错误、得分超满分 |
  侧栏与主界面同为浅色：侧栏底色 `#EDE9F7`（比画布 `#F7F6FA` 略深一档的淡紫），右侧 1px `#DFD8EE` 分隔线，选中项填充 `#E6DAF7` 并使用深紫文字 `#4A3A6B`，悬停 `#E6E0F3`。
- **样式集中管理**：所有颜色、圆角、表头、选中态、禁用态、滚动条都在 `resources/styles/app.qss`。页面不再散落 `setStyleSheet`，控件通过动态属性 `uiRole`（`primary`、`danger`、`save`、`saved`、`hint`、`status`、`error`、`success`、`warning`、`banner`、`invalid`、`section`）选择变体，改动样式只需编辑 qss。
- **公共构件**：`src/ui/UiKit.h` 提供 `makePageLayout`、`makePageTitle`、`makePageDescription`、`makeSectionTitle`、`makeHintLabel`、`makeStatusLabel`、`makeErrorLabel`、`makeFilterBar`、`confirmDanger` 以及带角色的按钮工厂，保证各页面边距（24px）与控件间距一致；`src/ui/TagDelegate.h` 把分类文本画成圆角标签。
- **成绩表**：`QTableView` + `ScoreTableModel`（`src/ui/ScoreTableModel.*`）+ `ScoreFilterProxyModel`。筛选（类型/科目/日期/关键字）与排序全部在 proxy 内完成，**不会重新查询数据库，也不会重建控件**；关键字输入有 180ms 防抖。得分率低于 60% 的单元格以警示色显示，得分高于满分的单元格以错误色显示。整表查询在 `QtConcurrent` 工作线程执行，工作线程使用独立连接。
- **列配置**：成绩表工具栏的「列」菜单可勾选显示/隐藏任意列，选择保存在 `settings` 的 `ui.score_hidden_columns` 键中，重启后恢复；「显示全部列」一键复位。
- **汇总页**：页内 `QTabWidget` 分为「汇总表」与「成绩趋势」。统计在 `QtConcurrent` 工作线程执行，工作线程使用独立 SQLite 连接（WAL 支持并发读）；结果通过 `QFutureWatcher` 回到 UI 线程。平均得分率用轻量自绘条形展示；趋势图使用 Qt Charts 的 `QChartView`（`LineSeries` + `ScatterSeries`），按科目展示得分率随日期的变化，横轴日期、纵轴 0–100%。
- **空状态**：成绩页区分「还没有成绩记录」与「没有符合筛选条件的成绩」，后者提供“清除筛选条件”；汇总页区分「还没有成绩记录」与「所选时间范围内没有成绩」；趋势标签页在所选科目无记录时给出提示。

## 交互约定

- 删除成绩、删除科目、停用科目都会二次确认；确认框使用中文动作按钮（删除/停用），默认焦点在“取消”。被成绩引用的科目删除按钮直接禁用并给出提示，只能停用。
- 成绩编辑对话框采用就近校验：必填项/分数不合法时在对话框内显示红色错误与红框，不再弹出消息框；仅“得分高于满分”在保存时弹一次确认。
- 学生档案页是一个显式的三态操作流：内容与数据库一致时保存按钮变为灰色 `已保存`（禁用）并隐藏撤销；一旦有改动（含中文输入法提交）立即变为浅绿 `保存修改` 并显示 `撤销更改`；保存后按钮回到灰色 `已保存`，同时显示 `撤销修改`——点击会把表单回填为保存前的内容（需再次点击 `保存修改` 才写入数据库，不会静默改动数据）。
- 设置页沿用同一套保存按钮约定：默认灰色 `已保存`（禁用、无撤销），切换日志级别后变为浅绿 `保存设置` 并显示 `撤销更改`，保存后回到 `已保存` 并显示 `撤销修改`。保存结果的反馈改由按钮胶囊表达，提示标签只用于错误信息。
- 标准对话框（文件选择、文本输入）通过 Qt 自带的 `qtbase_zh_CN` 翻译显示中文。
- 快捷键均限定在所属页面（`WidgetWithChildrenShortcut`），不会与其他页面同名快捷键冲突：成绩页 `Ctrl+N` 新增、`Ctrl+E` 导出、`Ctrl+F` 聚焦搜索、`F2` 编辑、`Delete` 删除；科目页 `Ctrl+N` 新增、`F2` 编辑、`Delete` 删除；档案/设置页 `Ctrl+S` 保存；汇总页 `Ctrl+E` 导出；日志页 `F5` 刷新。
- 所有页面使用布局管理器，无 `setGeometry` 绝对定位。

## 手工验收清单

1. 启动应用：左侧导航为浅紫底色、当前页以淡紫填充高亮，页面背景浅灰、表格白底，字体统一（微软雅黑）；整体无深色面板。
2. 在 100% 与 150% 缩放（或 `QT_SCALE_FACTOR=1.5`）下检查：窗口可缩放、无控件重叠或截断，表格与表单自适应；最小尺寸 1024×680 下筛选栏不重叠。
3. 成绩管理：录入 1000+ 条数据后滚动、点击表头排序、切换类型/科目/日期/关键字筛选，均应即时响应且不重建页面；得分率 <60% 显示警示色。
4. 成绩新增/编辑：清空考试名称或把满分改为 0，应立即出现红框与错误文字；保存“得分高于满分”时弹一次确认。
5. 删除成绩：弹出二次确认，动作为“删除/取消”，默认焦点在“取消”。
6. 科目管理：类型与状态显示为彩色圆角标签（OI 蓝紫、文化课黄绿、启用薄荷绿）；选中被引用科目时“删除”为禁用并提示“只能停用”；停用后新成绩不再可选，但历史成绩仍可编辑。
7. 成绩汇总：切换全部时间/本学期/自定义，统计随之刷新；平均得分率显示条形；无数据时显示空状态而不是空表。
8. 导出：成绩明细导出当前筛选结果，汇总导出当前时间范围；UTF-8 BOM，Excel 可直接打开。
9. 设置/日志：窗口默认浅色，日志为等宽字体；切换日志级别后保存按钮变为浅绿 `保存设置`、「撤销更改」出现，保存后按钮变为灰色 `已保存` 并出现 `撤销修改`。
10. 学生档案：未改动时保存按钮为灰色 `已保存` 且看不到撤销；修改姓名/所在学段/入学年份/目标院校后变为浅绿 `保存修改` 并出现 `撤销更改`；保存后按钮回到 `已保存` 且出现 `撤销修改`，点击可回填保存前内容。表单下方实时显示“按当前系统日期推算：初中·2年级”之类的年级提示。
11. 重启应用：窗口尺寸、最后页面保持不变。侧栏标题下方显示粗体姓名、灰色年级文字与“目标：…”灰色小字；目标院校未填写时该行隐藏，未建档时整个学生信息块隐藏。
12. 分组侧栏：顶层显示「档案」「考试」「设置」；「考试」「设置」加粗且带展开箭头，点击可展开/收起；子项缩进显示，当前页高亮；重启后仍停留在上次的子页面。
13. 成绩趋势：进入「成绩汇总 → 成绩趋势」，切换科目下拉框，折线随该科目考试日期与得分率变化；无记录时显示提示而不是空白图；切换时间范围后趋势同步刷新。
14. 列配置：在成绩页通过「列」菜单隐藏若干列（如“备注”“参考人数”），关闭并重启应用后隐藏状态保持；「显示全部列」可一键恢复。
15. 快捷键：`Ctrl+1…6` 在任意页面切换；成绩页 `Ctrl+F` 聚焦搜索、`F2` 编辑、`Delete` 删除（需先选中行）；日志页 `F5` 刷新。
16. 年级推算：把系统日期改到 9 月 1 日之后（或修改档案的入学年份），侧栏年级与档案页提示随之变化；`初中 3 年级 → 高中 1 年级`、`小学 6 年级 → 初中 1 年级`、高中满三年显示“已毕业”。
17. 导出数据库：设置页「导出数据库…」保存到任意位置，得到一个可独立打开的 `.db`；用「导入数据库…」选中它，二级验证窗口的「覆盖并导入」在输入「导入」前保持禁用。
18. 导入覆盖：先记录一批成绩，再导入另一份 `.db`，确认后所有页面（档案、科目、成绩、汇总、侧栏姓名）立即显示导入文件的数据，且 `backups/` 下新增一份导入前快照。
19. 重置数据：输入「重置」并确认后，档案页回到首次启动状态、侧栏姓名/年级/目标整块隐藏、科目与成绩清空；`backups/` 下新增 `cutee-before-reset-*.db`，日志级别与窗口位置保持不变。

## 性能设计

- 成绩表筛选/排序不触碰数据库：`reload()` 仅在进入页面、显式刷新或 CRUD 后重新查询一次，其余交互只更新 proxy。
- 整表查询在 `QtConcurrent` 工作线程执行（独立 SQLite 连接），结果通过 `QFutureWatcher` 回到 UI 线程；查询进行中再次刷新会合并为一次待处理请求，不会堆积任务。
- 关键指标（本机 MinGW Debug 构建，1500 条成绩）：查询 + 模型重置 + 视图刷新约 **12ms**；启动到主窗口可见约 **0.4s**；表头排序与筛选无可感知延迟。
- 汇总统计一律异步执行（即使耗时很短），避免数据量增大后阻塞界面；工作线程每次统计使用独立连接，结束后关闭。
- 科目页的“成绩引用”改为单条 `GROUP BY` 查询，不再按行 N+1 查询。

## 已知限制

- 仅维护一位学生，无法新增第二位；如需更换学生请直接编辑档案。
- 科目类型创建后不可修改（避免与已有成绩的 `exam_type` 冲突），请新建科目。
- 科目只有“停用”而没有级联删除：删除被引用的科目会被拒绝。
- 成绩导入（CSV）尚未实现，仅支持导出；`detail_json` 尚未提供 UI。
- 汇总中的“平均得分”“最高/最低分”按原始分数计算；同一科目满分不同的考试请结合“平均得分率”判断。
- 无网络、账号、云同步功能。
- 界面仅提供浅色主题；深色主题属于后续可选项。
- 成绩趋势依赖 Qt Charts 附加模块（GPLv3 / 商业双许可）。若发行包以 LGPL 方式使用 Qt，需要评估该模块的许可影响，或改用自绘 `QPainter` 图表。
